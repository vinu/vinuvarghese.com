# VR-Viewable Portfolio Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the portfolio walkable in a VR headset — a floating-panel gallery of the resume content, reachable via `/vr`, with a WebXR-detection banner on the normal site and a no-headset desktop fallback for testing.

**Architecture:** A new Astro page (`/vr`) mounts a client-only React island built with `@react-three/fiber` + `@react-three/xr` (the same R3F paradigm already used by `HeroScene.tsx`). The scene renders 4 floating text panels (About/Experience/Skills/Contact, sourced from the existing `src/data/resume.ts`) arranged in a circle. Movement is point-and-teleport in VR, or WASD + mouse-drag on desktop — the same scene serves both, which is also the no-headset test path. A small banner on the existing homepage checks `navigator.xr.isSessionSupported('immersive-vr')` and links to `/vr` only when a headset is actually detected.

**Tech Stack:** `@react-three/xr` (WebXR for R3F), `@react-three/drei`'s `<Text>` (in-scene 3D text — NOT `<Html>`, which does not render inside an active immersive session), `@types/webxr` (ambient WebXR types).

## Global Constraints

- Node v24 required; Astro 7 needs Node >= 22.12 (from `.nvmrc` / `CLAUDE.md`).
- No test framework is configured in this repo. Verification is `npm run build` (compiles cleanly) plus manual `npm run dev` browser checks — this plan follows that existing convention rather than introducing a test runner.
- Design system ("engineering blueprint"): square corners everywhere — never use Tailwind `rounded-*` classes. Labels/prompts use `font-mono`. The single accent is cobalt: `text-cobalt dark:text-cobalt-bright`, `border-cobalt dark:border-cobalt-bright`. Light-mode styles are the unprefixed base; dark-mode uses `dark:`.
- New dependencies, exact versions verified peer-compatible with the installed `@react-three/fiber@^9.6.1`, `three@^0.185.1`, `react@^19.2.7`: `@react-three/xr@^6.6.30`, `@react-three/drei@^10.7.8`, `@types/webxr@^0.5.24` (dev).
- When committing, stage only the files each task names, by exact path — never `git add -A`. This repo has unrelated untracked Claude Code tooling directories (`.agents/`, `.claude/`, `.impeccable/`, etc.) that must never be swept into a commit.
- Design spec: `docs/superpowers/specs/2026-08-11-vr-portfolio-design.md`. Its "Non-goals" section (AR mode, hand-tracking, spatial audio, per-section themed rooms, custom controller models, multiplayer, automated WebXR test coverage) is out of scope for every task below — do not add any of it.

- [ ] **Step 1: Write `Panel.tsx`**

A single floating placard: a dark background plane behind a heading and a body of wrapped text, both real 3D geometry (`@react-three/drei`'s `<Text>`, not `<Html>` — `<Html>` does not render inside an active immersive WebXR session, only in the flat/desktop view, so it would silently break for real headset users).

```tsx
import { Text } from '@react-three/drei';
import type { VrPanelData } from '../../data/vrPanels';

const PANEL_WIDTH = 1.8;
const PANEL_HEIGHT = 1.3;

interface PanelProps {
  data: VrPanelData;
  position: [number, number, number];
  rotationY: number;
}

export default function Panel({ data, position, rotationY }: PanelProps) {
  return (
    <group position={position} rotation={[0, rotationY, 0]}>
      <mesh position={[0, 0, -0.01]}>
        <planeGeometry args={[PANEL_WIDTH, PANEL_HEIGHT]} />
        <meshBasicMaterial color="#100f0d" transparent opacity={0.92} />
      </mesh>
      <Text
        position={[-PANEL_WIDTH / 2 + 0.12, PANEL_HEIGHT / 2 - 0.16, 0]}
        fontSize={0.09}
        color="#5b9fe8"
        anchorX="left"
        anchorY="top"
      >
        {`/${data.index} ${data.title}`}
      </Text>
      <Text
        position={[-PANEL_WIDTH / 2 + 0.12, PANEL_HEIGHT / 2 - 0.34, 0]}
        fontSize={0.055}
        lineHeight={1.5}
        maxWidth={PANEL_WIDTH - 0.24}
        color="#f5f2ea"
        anchorX="left"
        anchorY="top"
      >
        {data.body}
      </Text>
    </group>
  );
}
```

`<Text>` uses drei's default bundled font (fetched at runtime) rather than the site's JetBrains Mono — matching the brand font in 3D space would mean sourcing and hosting a `.ttf`/`.otf`/`.woff` for troika-three-text, which is real extra work with no functional payoff for v1. Noted here rather than silently skipped; revisit only if the mismatch bothers you in practice.

- [ ] **Step 2: Write `DesktopFlyControls.tsx`**

WASD + drag-to-look camera controller for the no-headset path. Only ever mounted outside an active XR session (see Step 3).

```tsx
import { useEffect, useRef } from 'react';
import { useFrame, useThree } from '@react-three/fiber';

const MOVE_SPEED = 2.5;
const LOOK_SPEED = 0.0025;
const MAX_PITCH = Math.PI / 2 - 0.05;

export default function DesktopFlyControls() {
  const { camera, gl } = useThree();
  const keys = useRef<Record<string, boolean>>({});
  const dragging = useRef(false);
  const yaw = useRef(camera.rotation.y);
  const pitch = useRef(camera.rotation.x);

  useEffect(() => {
    const onKeyDown = (e: KeyboardEvent) => {
      keys.current[e.code] = true;
    };
    const onKeyUp = (e: KeyboardEvent) => {
      keys.current[e.code] = false;
    };
    const onPointerDown = () => {
      dragging.current = true;
    };
    const onPointerUp = () => {
      dragging.current = false;
    };
    const onPointerMove = (e: PointerEvent) => {
      if (!dragging.current) return;
      yaw.current -= e.movementX * LOOK_SPEED;
      pitch.current = Math.max(
        -MAX_PITCH,
        Math.min(MAX_PITCH, pitch.current - e.movementY * LOOK_SPEED)
      );
    };

    const canvas = gl.domElement;
    window.addEventListener('keydown', onKeyDown);
    window.addEventListener('keyup', onKeyUp);
    canvas.addEventListener('pointerdown', onPointerDown);
    window.addEventListener('pointerup', onPointerUp);
    window.addEventListener('pointermove', onPointerMove);
    return () => {
      window.removeEventListener('keydown', onKeyDown);
      window.removeEventListener('keyup', onKeyUp);
      canvas.removeEventListener('pointerdown', onPointerDown);
      window.removeEventListener('pointerup', onPointerUp);
      window.removeEventListener('pointermove', onPointerMove);
    };
  }, [gl]);

  useFrame((_, delta) => {
    camera.rotation.set(pitch.current, yaw.current, 0, 'YXZ');

    const forward = keys.current['KeyW'] ? 1 : keys.current['KeyS'] ? -1 : 0;
    const strafe = keys.current['KeyD'] ? 1 : keys.current['KeyA'] ? -1 : 0;
    if (forward === 0 && strafe === 0) return;

    const sinYaw = Math.sin(yaw.current);
    const cosYaw = Math.cos(yaw.current);
    const distance = MOVE_SPEED * delta;
    camera.position.x += (-sinYaw * forward + cosYaw * strafe) * distance;
    camera.position.z += (-cosYaw * forward - sinYaw * strafe) * distance;
  });

  return null;
}
```

- [ ] **Step 3: Write `VrScene.tsx`**

Lights, the 4 panels arranged in a circle (radius 3, eye height 1.5), a teleport-enabled ground plane, and the XR player origin. Panel 0 sits directly at `[0, 1.5, -3]` — straight ahead of the default camera (three.js cameras look down `-Z`), so both the VR view and the desktop fallback start with a panel already in view.

```tsx
import { useState } from 'react';
import { Vector3 } from 'three';
import { TeleportTarget, XROrigin, useXR } from '@react-three/xr';
import { vrPanels } from '../../data/vrPanels';
import Panel from './Panel';
import DesktopFlyControls from './DesktopFlyControls';

const PANEL_RADIUS = 3;
const PANEL_HEIGHT = 1.5;

export default function VrScene() {
  const [position, setPosition] = useState(new Vector3(0, 0, 0));
  const session = useXR((state) => state.session);

  return (
    <>
      <ambientLight intensity={0.9} />
      <directionalLight position={[3, 5, 2]} intensity={0.6} />

      <XROrigin position={position} />

      {vrPanels.map((panel, i) => {
        const angle = (i * Math.PI) / 2;
        return (
          <Panel
            key={panel.index}
            data={panel}
            position={[
              Math.sin(angle) * PANEL_RADIUS,
              PANEL_HEIGHT,
              -Math.cos(angle) * PANEL_RADIUS,
            ]}
            rotationY={-angle}
          />
        );
      })}

      <TeleportTarget onTeleport={setPosition}>
        <mesh position={[0, -0.5, 0]}>
          <boxGeometry args={[16, 1, 16]} />
          <meshStandardMaterial color="#1e1c18" />
        </mesh>
      </TeleportTarget>

      {session == null && <DesktopFlyControls />}
    </>
  );
}
```

- [ ] **Step 4: Write `VrExperience.tsx`**

Owns the `XRStore`, the "Enter VR" button (a plain button — this version of `@react-three/xr` has no `<XRButton>` component, you call `store.enterVR()` directly), and the `Canvas`/`XR` wrapper.

```tsx
import { Canvas } from '@react-three/fiber';
import { createXRStore, XR } from '@react-three/xr';
import VrScene from './VrScene';

const store = createXRStore({
  hand: { teleportPointer: true },
  controller: { teleportPointer: true },
});

export default function VrExperience() {
  return (
    <div className="relative w-full h-svh overflow-hidden bg-night">
      <div className="absolute top-4 inset-x-0 z-10 flex flex-col items-center gap-2 pointer-events-none">
        <button
          onClick={() => {
            store.enterVR().catch(() => {});
          }}
          className="pointer-events-auto font-mono text-xs border border-cobalt-bright text-cobalt-bright bg-night/90 px-4 py-2"
        >
          Enter VR
        </button>
        <p className="font-mono text-[10px] text-stone-400">
          no headset? drag to look, WASD to move
        </p>
      </div>
      <Canvas camera={{ position: [0, 1.5, 0], fov: 60 }} gl={{ antialias: true }}>
        <XR store={store}>
          <VrScene />
        </XR>
      </Canvas>
    </div>
  );
}
```

`.catch(() => {})` on `enterVR()` swallows the rejected promise you get on any browser without WebXR support, so clicking the button on a plain desktop browser fails quietly instead of logging an unhandled-rejection error.

- [ ] **Step 1: Write `VrPrompt.tsx`**

```tsx
import { useEffect, useState } from 'react';

export default function VrPrompt() {
  const [supported, setSupported] = useState(false);
  const [dismissed, setDismissed] = useState(false);

  useEffect(() => {
    if (typeof navigator === 'undefined' || !navigator.xr) return;
    let cancelled = false;
    navigator.xr
      .isSessionSupported('immersive-vr')
      .then((ok) => {
        if (!cancelled) setSupported(ok);
      })
      .catch(() => {});
    return () => {
      cancelled = true;
    };
  }, []);

  if (!supported || dismissed) return null;

  return (
    <div role="status" className="fixed bottom-6 inset-x-0 z-40 flex justify-center px-4">
      <div className="flex items-center gap-4 border border-cobalt dark:border-cobalt-bright bg-paper dark:bg-night px-4 py-3 font-mono text-xs">
        <span>VR headset detected —</span>
        <a href="/vr" className="text-cobalt dark:text-cobalt-bright underline underline-offset-4">
          enter 3D portfolio
        </a>
        <button
          onClick={() => setDismissed(true)}
          aria-label="Dismiss"
          className="text-stone-500 dark:text-stone-400 hover:text-cobalt dark:hover:text-cobalt-bright"
        >
          ×
        </button>
      </div>
    </div>
  );
}
```
